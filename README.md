# Trusted PC Control — Telegram Mini App

Локальная система управления **собственными** ПК: Telegram Mini App → сервер → агент на компьютере → результат. Сервер не выполняет shell-команды и не имеет универсального API исполнения команд; агент принимает только фиксированный список действий.

## Что реализовано

- привязка агента одноразовым 15-минутным кодом, уникальный UUID устройства и отдельный секрет на устройство;
- доступ к WebApp и командам только после криптографической проверки `initData` Telegram и совпадения `OWNER_TELEGRAM_ID`;
- список нескольких ПК, Online/Offline (таймаут heartbeat 45 секунд), ОС, IP, uptime, CPU, RAM и диски;
- heartbeat раз в 5 секунд с автоматическим восстановлением после сети/перезапуска;
- очередь команд, результаты и SQLite-журнал последних действий;
- скриншот (сохраняется локально в `screenshots/` и приходит владельцу в Telegram), блокировка, выключение, перезапуск, список процессов;
- запуск/закрытие **только** приложений из `ALLOWED_APPS` в `agent.py`; отсутствует произвольное выполнение команд;
- подтверждение выключения и перезагрузки в Mini App.

## Очень простая инструкция для Windows

Ниже — путь, рассчитанный на человека без опыта. Сначала поднимите **сервер на одном своём ПК**, затем к нему можно подключить этот же или другой свой компьютер. Все окна с запущенными программами должны оставаться открытыми.

> **Стоп: если у вас Windows, НЕ вводите `cd /workspace/botbolz`, `. .venv/bin/activate` и `cp .env.example .env`.** Это команды для Linux и рабочего компьютера разработчика, на вашем ПК такой папки не существует. Если PowerShell показывает что-то вроде `PS C:\Users\...\Desktop\brotbots>`, вы уже находитесь в правильной папке проекта. Просто следуйте шагам ниже и нажимайте `.bat`-файлы двойным кликом.

### Шаг 1. Скачать проект

Если проект лежит на GitHub: на странице проекта нажмите зелёную кнопку **Code** → **Download ZIP**. Распакуйте ZIP, например, в `C:\pc-control`. Если у вас уже есть папка проекта — этот шаг пропустите.

### Шаг 2. Установить Python

1. Откройте [страницу загрузки Python](https://www.python.org/downloads/).
2. Скачайте Python **3.11 или новее** для Windows и запустите установщик.
3. На первом экране обязательно включите галочку **Add Python to PATH**, затем нажмите **Install Now**.
4. Перезагрузите Windows, если установщик попросит об этом.

**Что такое «библиотеки» и почему они устанавливаются?** Это обычные дополнительные компоненты Python, без них программа не запустится. Ничего вручную писать в PowerShell для их установки не надо: при первом двойном клике по `start_server_windows.bat` появится чёрное окно, оно само скачает всё нужное. Дождитесь надписи `Uvicorn running ...`; это может занять несколько минут только при первом запуске.

### Шаг 3. Создать Telegram-бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather), нажмите **Start**, отправьте `/newbot`.
2. Введите имя и username бота. BotFather пришлёт токен вида `123456:ABC...` — это пароль бота, никому его не показывайте.
3. Узнайте свой Telegram ID: отправьте любое сообщение [@userinfobot](https://t.me/userinfobot) и скопируйте число из ответа.

### Шаг 4. Подготовить настройки — очень подробно

1. Откройте папку, куда вы распаковали проект. В вашем примере это `C:\Users\хер в мясе\Desktop\brotbots`.
2. Найдите файл `.env.example`.
3. Нажмите на нём правой кнопкой → **Копировать**, затем на пустом месте папки → **Вставить**.
4. Переименуйте созданную копию в **`.env`** (без `.txt`). Если Windows не даёт убрать `.txt`: в проводнике нажмите «Вид» → «Показать» → «Расширения имён файлов», затем повторите переименование.
5. Нажмите на `.env` правой кнопкой → «Открыть с помощью» → «Блокнот». Заполните **только** эти строки:

```ini
OWNER_TELEGRAM_ID=ваш_числовой_ID
OWNER_API_KEY=придумайте_длинный_случайный_пароль_минимум_32_символа
TELEGRAM_BOT_TOKEN=токен_от_BotFather
PUBLIC_BASE_URL=
```

Пока оставьте `PUBLIC_BASE_URL` пустым, сохраните файл и не пересылайте его никому.

### Шаг 5. Запустить сервер — только двойной клик

1. В этой же папке дважды нажмите `start_server_windows.bat`. **Не нужно сначала вводить `cd` или другие команды.**
2. При первом запуске подождите: чёрное окно само создаст служебную папку `.venv` и скачает библиотеки. Не закрывайте его.
3. Всё получилось, когда увидите строку `Uvicorn running on http://0.0.0.0:8000`. Окно оставьте открытым.
4. Теперь дважды нажмите **`start_tunnel_windows.bat`**. Он проверит, установлен ли `cloudflared`, и при необходимости сам попробует установить его через Windows. **Не вводите `cloudflared ...` вручную в PowerShell.**
5. Если Windows спросит разрешение на установку — согласитесь. После успешной установки закройте это окно и ещё раз дважды нажмите `start_tunnel_windows.bat`.
6. Откроется отдельное чёрное окно с заголовком **`PC Control tunnel - DO NOT CLOSE`**. Оно **должно оставаться открытым**. В нём появится адрес наподобие `https://orange-dog.trycloudflare.com`. Это **не секретный ключ**, а временный интернет-адрес вашей панели. Скопируйте его.
7. Вернитесь к `.env`, вставьте этот адрес после `PUBLIC_BASE_URL=`, сохраните файл. Закройте окно `start_server_windows.bat` и запустите его снова.
8. В PowerShell выполните команду ниже, вставив свой адрес и токен вместо примеров:

```powershell
Invoke-RestMethod -Uri "https://api.telegram.org/botВАШ_ТОКЕН/setWebhook?url=ВАШ_PUBLIC_BASE_URL/telegram/webhook"
```

9. Откройте своего бота в Telegram и отправьте `/start`. Появится кнопка **«🖥 Панель ПК»**.

> Важно: адрес `trycloudflare.com` временный. После закрытия окна туннеля создайте новый адрес, поменяйте `PUBLIC_BASE_URL`, перезапустите сервер и повторите настройку webhook из пункта 8. Для постоянной работы настройте именованный Cloudflare Tunnel.

**Если окно с заголовком `PC Control tunnel - DO NOT CLOSE` не появилось:** обновите файлы проекта и повторите. Если оно появилось, но в нём красная ошибка — сделайте скриншот этого окна и пришлите его. Не присылайте содержимое `.env`, токен бота, `OWNER_API_KEY` или код привязки.

### Если `.bat`-файл закрывается: запуск туннеля прямо в терминале

Это нормальный и более надёжный способ: окно PowerShell уже открыто, поэтому оно не закроется само.

1. Убедитесь, что окно `start_server_windows.bat` уже работает и в нём есть `Uvicorn running ...`.
2. Нажмите **Пуск**, напишите `PowerShell`, нажмите **Windows PowerShell**.
3. Сначала вставьте и нажмите Enter:

```powershell
where.exe cloudflared
```

4. Если увидели путь, например `C:\Program Files (x86)\cloudflared\cloudflared.exe`, вставьте следующую команду и нажмите Enter:

```powershell
cloudflared tunnel --url http://localhost:8000
```

Не закрывайте PowerShell. В нём будет адрес `https://...trycloudflare.com`, который нужно вставить в `PUBLIC_BASE_URL`.

5. Если команда `where.exe cloudflared` **ничего не вывела**, выполните установку ещё раз:

```powershell
winget install --id Cloudflare.cloudflared -e --accept-package-agreements --accept-source-agreements
```

После завершения **закройте PowerShell, откройте новый PowerShell** и повторите пункты 3–4. Если `where.exe` по-прежнему ничего не выводит, запустите туннель полной командой:

```powershell
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:8000
```

### Шаг 6. Подключить компьютер

1. На компьютере с сервером откройте PowerShell в папке проекта: в проводнике откройте папку, кликните по пустому месту с зажатым **Shift** → «Открыть в Терминале».
2. Выполните команду, заменив `ВАШ_PUBLIC_BASE_URL` и `ВАШ_ДЛИННЫЙ_ПАРОЛЬ` значениями из `.env`:

```powershell
Invoke-RestMethod -Method Post -Uri "ВАШ_PUBLIC_BASE_URL/api/admin/pairings" -Headers @{ Authorization = "Bearer ВАШ_ДЛИННЫЙ_ПАРОЛЬ" }
```

3. В ответе скопируйте значение `pairing_code`.
4. На подключаемом ПК скопируйте всю папку проекта. Дважды нажмите `start_agent_windows.bat`. Введите адрес и одноразовый код, когда программа попросит их. При первом запуске она сама установит нужные библиотеки.

5. Откройте Mini App в Telegram. Компьютер появится в списке; второй ПК подключается точно так же, но с **новым** одноразовым кодом.

## Linux/macOS: запуск вручную (не используйте этот раздел в Windows)

Требования: Python 3.11+ и публичный HTTPS URL для Telegram (например, reverse proxy или Cloudflare Tunnel).

```bash
cd /workspace/botbolz
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# отредактируйте .env: OWNER_TELEGRAM_ID, OWNER_API_KEY, TELEGRAM_BOT_TOKEN, PUBLIC_BASE_URL
uvicorn server:app --host 0.0.0.0 --port 8000
```

Установите webhook после того, как `PUBLIC_BASE_URL` доступен по HTTPS:

```bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook?url=$PUBLIC_BASE_URL/telegram/webhook"
```

Отправьте `/start` боту с Telegram-аккаунта владельца. Бот выдаст кнопку **«🖥 Панель ПК»**. Другие аккаунты не получают интерфейс, а API дополнительно отклоняет их `initData`.

## Привязка каждого компьютера

На доверенной машине администратора с доступом к серверу создайте код (не передавайте его в чаты):

```bash
curl -X POST "$PUBLIC_BASE_URL/api/admin/pairings" \
  -H "Authorization: Bearer $OWNER_API_KEY"
```

На каждом ПК отдельно скопируйте проект/минимум `agent.py`, установите зависимости и привяжите агент:

```bash
pip install -r requirements.txt
python agent.py pair --server "https://your-public-https-url.example" --code "КОД_ИЗ_ОТВЕТА"
python agent.py run
```

Для автозапуска используйте системный service manager (systemd/Windows Task Scheduler), запускающий `python agent.py run`. Файл `agent-state.json` содержит секрет устройства: оставьте его доступным только учётной записи агента (`0600` задаётся автоматически в Unix) и не коммитьте его.

## Эксплуатация и безопасность

- Задайте случайный `OWNER_API_KEY` длиной не менее 32 байт (`python -c "import secrets; print(secrets.token_urlsafe(32))"`). `.env`, БД, `agent-state.json` и скриншоты не должны попадать в Git или публичные папки.
- Сервер принимает агентские запросы только с HMAC подписью тела, меткой времени (окно 5 минут) и секретом именно этого устройства. Код привязки одноразовый.
- Не публикуйте сервер без HTTPS. Ограничьте административный endpoint сетью/VPN reverse proxy, если возможно.
- На Linux выключение/reboot/lock могут требовать policykit/sudo-права; предоставляйте их только конкретной service-учётной записи и только для необходимых действий.
- Скриншот передаётся агентом только через аутентифицированный HTTPS-канал и сразу пересылается владельцу ботом; бинарные данные не записываются в SQLite. Для production рассмотрите зашифрованное файловое хранилище с короткоживущими ссылками для больших результатов.

## Ограничения MVP

Сервер отправляет владельцу уведомления о переходах Online/Offline, перезапуске клиента, ошибках команд и готовых скриншотах. Для production рекомендуется вынести этот фоновой worker и доставку уведомлений в отдельный устойчивый процесс, а также добавить защищённое хранилище для больших результатов. UI обновляет список и журнал каждые 10 секунд.
