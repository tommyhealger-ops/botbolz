# Trusted PC Control — Telegram Mini App

Локальная система управления **собственными** ПК: Telegram Mini App → сервер → агент на компьютере → результат. Сервер не выполняет shell-команды и не имеет универсального API исполнения команд; агент принимает только фиксированный список действий.

## Что реализовано

- привязка агента одноразовым 15-минутным кодом, уникальный UUID устройства и отдельный секрет на устройство;
- доступ к WebApp и командам только после криптографической проверки `initData` Telegram и совпадения `OWNER_TELEGRAM_ID`;
- список нескольких ПК, Online/Offline (таймаут heartbeat 45 секунд), ОС, IP, uptime, CPU, RAM и диски;
- heartbeat раз в 5 секунд с автоматическим восстановлением после сети/перезапуска;
- очередь команд, результаты и SQLite-журнал последних действий;
- скриншот (сохраняется локально в `screenshots/` и приходит владельцу в Telegram), блокировка, выключение, перезапуск, список процессов;
- запуск/закрытие **только** приложений из `ALLOWED_APPS` в `agent.py`; отсутствует произвольное выполнение команд;
- подтверждение выключения и перезагрузки в Mini App.

## Запуск сервера

Требования: Python 3.11+ и публичный HTTPS URL для Telegram (например, reverse proxy или Cloudflare Tunnel).

```bash
cd /workspace/botbolz
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# отредактируйте .env: OWNER_TELEGRAM_ID, OWNER_API_KEY, TELEGRAM_BOT_TOKEN, PUBLIC_BASE_URL
uvicorn server:app --host 0.0.0.0 --port 8000
```

Установите webhook после того, как `PUBLIC_BASE_URL` доступен по HTTPS:

```bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook?url=$PUBLIC_BASE_URL/telegram/webhook"
```

Отправьте `/start` боту с Telegram-аккаунта владельца. Бот выдаст кнопку **«🖥 Панель ПК»**. Другие аккаунты не получают интерфейс, а API дополнительно отклоняет их `initData`.

## Привязка каждого компьютера

На доверенной машине администратора с доступом к серверу создайте код (не передавайте его в чаты):

```bash
curl -X POST "$PUBLIC_BASE_URL/api/admin/pairings" \
  -H "Authorization: Bearer $OWNER_API_KEY"
```

На каждом ПК отдельно скопируйте проект/минимум `agent.py`, установите зависимости и привяжите агент:

```bash
pip install -r requirements.txt
python agent.py pair --server "https://your-public-https-url.example" --code "КОД_ИЗ_ОТВЕТА"
python agent.py run
```

Для автозапуска используйте системный service manager (systemd/Windows Task Scheduler), запускающий `python agent.py run`. Файл `agent-state.json` содержит секрет устройства: оставьте его доступным только учётной записи агента (`0600` задаётся автоматически в Unix) и не коммитьте его.

## Эксплуатация и безопасность

- Задайте случайный `OWNER_API_KEY` длиной не менее 32 байт (`python -c "import secrets; print(secrets.token_urlsafe(32))"`). `.env`, БД, `agent-state.json` и скриншоты не должны попадать в Git или публичные папки.
- Сервер принимает агентские запросы только с HMAC подписью тела, меткой времени (окно 5 минут) и секретом именно этого устройства. Код привязки одноразовый.
- Не публикуйте сервер без HTTPS. Ограничьте административный endpoint сетью/VPN reverse proxy, если возможно.
- На Linux выключение/reboot/lock могут требовать policykit/sudo-права; предоставляйте их только конкретной service-учётной записи и только для необходимых действий.
- Скриншот передаётся агентом только через аутентифицированный HTTPS-канал и сразу пересылается владельцу ботом; бинарные данные не записываются в SQLite. Для production рассмотрите зашифрованное файловое хранилище с короткоживущими ссылками для больших результатов.

## Ограничения MVP

Сервер отправляет владельцу уведомления о переходах Online/Offline, перезапуске клиента, ошибках команд и готовых скриншотах. Для production рекомендуется вынести этот фоновой worker и доставку уведомлений в отдельный устойчивый процесс, а также добавить защищённое хранилище для больших результатов. UI обновляет список и журнал каждые 10 секунд.
